SYSTEM ANALYSIS — Entrepreneur Queries Addressed
===============================================================================

The system supports three main areas:
1. POS Terminal (/pos/*) — PIN login, till, transactions, clock, checklists, goods-in
2. Head Office (/app/:slug/*) — Dashboard, sales, PLU, stores, users, suppliers, categories, 
   item sizing, POs, devices, loyalty, notifications, logbook
3. Platform Admin (/admin/*) — Tenants, plans, super users, settings

Entrepreneur queries addressed by this plan:
- "How much did we sell today/this week/this month?" → Dashboard Revenue card
- "Which products sell best?" → Report 2 (Sales by PLU)
- "What's our payment method split?" → Dashboard Payment Split card
- "Which store performs best?" → Report 4 (Sales by Store - not in initial 10)
- "What needs restocking?" → Dashboard Low Stock alert + Report 6 (Stock)
- "Are POs arriving on time?" → Report 4 (Purchase Orders)
- "Is loyalty driving repeat business?" → Report 3 (Loyalty Performance)
- "Are staff clocking in/out properly?" → Report 5 (Timesheets)
- "What's our cost of goods sold?" → Report 7 (COGS)
- "What goods came in?" → Report 8 (Goods In)
- "Can I export data for accounting/board?" → CSV + PDF exports on all reports
- "What PLUs do we have?" → Report 9 (PLU Master List)
- "Who are our users and stores?" → Report 10 (Users & Stores List)

===============================================================================
REPORTS SECTION — /app/:slug/Reporting/Reports
===============================================================================

Hero Section:
- Report Type Selector: Dropdown (10 initial reports)
- Date Range: Today / 7 Days / 30 Days / Custom
- Store Filter: All Stores + individual stores
- Format Selector: HTML / CSV / PDF
- Apply / Export Buttons

10 Initial Reports (Read-Only, Aggregation Only):

1. Sales Summary
   Data: sales_transactions + sale_items
   Aggregations: Total revenue, txn count, avg ticket, discounts, refunds, voids
   Grouping: By day/week/month

2. Sales by PLU
   Data: sale_items + plu
   Aggregations: Quantity, revenue, discount % per PLU; top/bottom performers

3. Loyalty Performance
   Data: loyalty_cards + sales_transactions
   Aggregations: Cards issued, active cards, cashback earned/used/redeemed, discount totals

4. Purchase Orders
   Data: purchase_orders + po_items + suppliers
   Aggregations: PO status (draft/ordered/partially_received/received), quantities ordered vs received, supplier performance (on-time %)

5. Timesheets (Clock In/Out)
   Data: staff_timesheets + users
   Aggregations: Clock-in/out times, hours worked, overtime, missing punches, late/early flags

6. Stock / Inventory
   Data: inventory + plu
   Aggregations: Current stock, threshold, value (stock × cost), low-stock flag, stock movement

7. COGS Report
   Data: sale_items + inventory + purchase_orders
   Aggregations: COGS = SUM(quantity × cost_per_unit) per PLU; Gross Margin = Revenue - COGS; Margin %

8. Goods In (Receiving)
   Data: purchase_orders + po_items + inventory
   Aggregations: Received quantities, received date, receiver, PO status, discrepancies

9. Lists — PLU Master
   Data: plu + plu_categories
   Fields: PLU ID, name, category, EAN, uses_scale, head-office price, per-store prices, active flag

10. Lists — Users & Stores
    Data: users + stores
    Fields: User: name, role, PIN status, assigned store, active; Store: name, address, active

TECHNICAL SPECIFICATIONS
===============================================================================

Data Access: Read-Only
- No API breaking changes — only new GET endpoints under /api/reports/*
- Server-side aggregation: SQL GROUP BY, SUM, COUNT, AVG, JOINs
- No writes: no INSERT, UPDATE, DELETE in report endpoints
- Tenant isolation: all queries scoped to tenant_schema via existing middleware

API Endpoints (BOTH server copies: apiPlugin.ts + api/[...path].ts):
GET /api/reports/list → [{ id, title, description, category }]
GET /api/reports/sales-summary?store_id=&date_from=&date_to=&format=html|csv|pdf
GET /api/reports/sales-by-plu?store_id=&date_from=&date_to=&format=html|csv|pdf
GET /api/reports/loyalty?store_id=&date_from=&date_to=&format=html|csv|pdf
GET /api/reports/purchase-orders?store_id=&date_from=&date_to=&format=html|csv|pdf
GET /api/reports/timesheets?store_id=&date_from=&date_to=&format=html|csv|pdf
GET /api/reports/stock?store_id=&date_from=&date_to=&format=html|csv|pdf
GET /api/reports/cogs?store_id=&date_from=&date_to=&format=html|csv|pdf
GET /api/reports/goods-in?store_id=&date_from=&date_to=&format=html|csv|pdf

Output Formats:
- HTML: Interactive view with sortable/filterable/paginated tables

- PDF: pdfmake/html2pdf — logo, title, period, summary, charts, tables, footer

===============================================================================
COGS CALCULATION NOTE
===============================================================================

Cost per unit source: Latest purchase_order_item.unit_cost for each PLU (weighted average if multiple recent POs)
Gross Margin = Revenue - COGS; Margin % = (Revenue - COGS) / Revenue * 100
