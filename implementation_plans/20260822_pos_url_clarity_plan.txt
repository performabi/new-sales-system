2026-08-22 IMPLEMENTATION PLAN — POS URL Clarity (tenant slug + store in URL)
================================================================================

Status legend: [ ] = not started   [~] = in progress   [x] = done   [!] = blocked

Objective: Make POS terminal URL show tenant slug + store (e.g. /pos/test_company/store_001/till)
so staff recognise which tenant/store they operate in. POS is already tenanted (JWT pos_token + pos_store_id
in sessionStorage) but URL is blind (/pos/till). No API break, no schema migration; URL is display-only,
token remains source of truth.

Design: /pos/:slug/:storeRef/*  where :slug = tenants.slug, :storeRef = stores.store_number (if present)
else 8-char store_id. Legacy /pos/* kept as redirect to canonical URL. Validation: URL slug/store must
match token's tenant/store; mismatch auto-corrects to token's canonical URL (prevents spoofing).
